# tg_export

Экспорт сообщений и медиа из чатов, групп и каналов Telegram в JSONL.

Утилита подключается к вашему аккаунту Telegram, показывает список доступных
диалогов и выгружает выбранный чат в директорию `exports/<название чата>/`:

- `messages.jsonl` — все сообщения (от новых к старым), по одному JSON на строку;
- `media/` — фото, видео, документы, голосовые, стикеры и т.д.

## Приватность

**Ваши данные никуда не передаются.** Утилита взаимодействует напрямую с
серверами Telegram по протоколу MTProto: никаких промежуточных серверов,
телеметрии и внешних сервисов в схеме нет. Всё, что скачано, остаётся на вашем
диске в `exports/`.

**Файл `session.json` — это доступ к вашему аккаунту.** В нём лежат приватные
ключи авторизации: кто угодно, получив этот файл, войдёт в ваш Telegram без
логина, пароля и второго фактора. Поэтому:

- никому не передавайте `session.json` и не выкладывайте его в репозитории,
  облака, чаты и архивы с логами;
- файл создаётся с правами `0600` (чтение и запись только владельцу) — не
  ослабляйте их;
- если файл всё же куда-то утёк, немедленно завершите сессию:
  Telegram → *Настройки → Устройства* → завершить нужный сеанс, после чего
  удалите `session.json` и авторизуйтесь заново.

То же касается `APP_ID`/`APP_HASH` и файла `.env` — это ваши личные учётные
данные приложения Telegram. Всё перечисленное уже перечислено в
[.gitignore](.gitignore), чтобы не попасть в git случайно.

## Требования

- `APP_ID` и `APP_HASH` — получить на https://my.telegram.org → *API development tools*.

## Установка

Скачайте готовый бинарник для своей платформы со страницы
[Releases](https://github.com/avissian/tg_export/releases):

| Платформа | Архив |
|-----------|-------|
| Windows (x86-64) | `tg_export_windows_amd64.zip` |
| Linux (x86-64) | `tg_export_linux_amd64.tar.gz` |
| macOS (Apple Silicon) | `tg_export_darwin_arm64.tar.gz` |

Распаковать и запустить:

```sh
tar -xzf tg_export_linux_amd64.tar.gz
./tg_export
```

На macOS первый запуск может быть заблокирован Gatekeeper — снять карантин:

```sh
xattr -d com.apple.quarantine ./tg_export
```

## Переменные окружения

Задаются через переменные окружения или файл `.env` в рабочей директории.

| Переменная | Обязательна | Описание |
|------------|-------------|----------|
| `APP_ID`   | да          | Telegram API ID (число) |
| `APP_HASH` | да          | Telegram API hash |
| `PHONE`    | только для `--code-auth` | Телефон в международном формате, напр. `+79991234567` |
| `ALL_PROXY` | нет | Прокси для подключения к Telegram, см. [Прокси](#прокси) |
| `HTTPS_PROXY`, `HTTP_PROXY` | нет | Резервные имена для того же адреса |
| `NO_PROXY` | нет | Хосты в обход прокси |

Пример `.env`:

```env
APP_ID=1234567
APP_HASH=abcdef0123456789abcdef0123456789
PHONE=+79991234567
ALL_PROXY=socks5://127.0.0.1:1080
```

## Прокси

Адрес берётся из переменных окружения (в том числе из `.env`) в таком порядке
приоритета: `ALL_PROXY` → `all_proxy` → `HTTPS_PROXY` → `https_proxy` →
`HTTP_PROXY` → `http_proxy`. Первое непустое значение и используется.

Поддерживаются схемы:

| Формат | Пример |
|--------|--------|
| SOCKS5 | `socks5://127.0.0.1:1080` |
| SOCKS5 с логином | `socks5://user:pass@host:1080` |
| SOCKS5 с DNS на стороне прокси | `socks5h://host:1080` |
| без схемы — считается SOCKS5 | `127.0.0.1:1080` |
| HTTP-прокси (через `CONNECT`) | `http://proxy.local:3128` |
| HTTPS-прокси (TLS до прокси) | `https://proxy.local:443` |

Порт можно не указывать — подставится стандартный (1080 для SOCKS5, 80/443 для
HTTP/HTTPS).

Особенности:

- Telegram работает по MTProto поверх обычного TCP, а не по HTTP. Поэтому
  HTTP(S)-прокси используется в режиме `CONNECT`-туннеля: прокси должен
  разрешать `CONNECT` на порты Telegram (443/80). Прокси, умеющий только
  проксировать HTTP-запросы, не подойдёт — берите SOCKS5.
- `NO_PROXY` учитывается: перечисленные в нём хосты и подсети идут напрямую.
- Если адрес прокси задан, но разобрать его не удалось, утилита завершается с
  ошибкой и **не** ходит в Telegram напрямую — чтобы ваш реальный IP не утёк
  мимо прокси.
- При старте в лог выводится используемый прокси, пароль в выводе скрыт.

```sh
ALL_PROXY=socks5://127.0.0.1:1080 ./tg_export
```

MTProxy (`https://t.me/proxy?server=...`) пока не поддерживается — только
SOCKS5 и HTTP(S).

Либо передать переменные прямо при запуске:

```sh
APP_ID=1234567 APP_HASH=abc... ./tg_export
```

## Авторизация

По умолчанию — вход по **QR-коду**: в терминале появится QR, отсканируйте его в
Telegram → *Настройки → Устройства → Подключить устройство*.

Альтернатива — вход по **коду из SMS/приложения** (нужен `PHONE`):

```sh
./tg_export --code-auth
```

Сессия сохраняется в `session.json`, при следующих запусках повторная
авторизация не требуется.

## Выбор чата и объёма выгрузки

После авторизации выводится список диалогов **по 25 на страницу**. Управление:

| Ввод | Действие |
|------|----------|
| номер | выбрать чат для экспорта (нумерация сквозная по всему списку) |
| `n` или Enter | следующая страница |
| `p` | предыдущая страница |
| `q` | выход |

Затем утилита спросит, **сколько последних сообщений экспортировать**. Введите
`0`, чтобы выгрузить всю историю целиком.

Прерывание по `Ctrl+C` безопасно; уже скачанные медиафайлы при повторном запуске
не загружаются заново.

## Для самостоятельной сборки из исходников

Нужен Go 1.26+.

Собрать и запустить:

```sh
go build -o tg_export .
./tg_export
```

Или без сборки:

```sh
go run .
```

Релизные бинарники собираются автоматически в GitHub Actions при пуше тега вида
`v1.0.0` — см. [.github/workflows/release.yaml](.github/workflows/release.yaml).
